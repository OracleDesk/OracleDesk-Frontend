# Internationalisation (i18n)

Status: the message-catalog foundation is in place (typed keys, ICU messages, catalog checker, pseudo-locale). **Locale-prefixed routing (`/de/markets`) is not implemented yet.** See "Not yet done" below.

## How it works

- Catalogs are JSON in `lib/i18n/messages/`: `en.json` is the source of truth, `en-XA.json` is a generated pseudo-locale.
- Messages are [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/) (`{name}`, `plural`, `select`), formatted with `intl-messageformat`.
- Message keys are checked at compile time. `t("does.not.exist")` fails `npm run typecheck`, and so does a missing or wrongly typed argument (`lib/i18n/message-params.generated.ts` is generated from the catalog).
- React components use `useTranslations()` from `lib/i18n/provider`. Code outside React uses `createServerlessTranslator(currentLocale())` from `lib/i18n`.
- The provider renders `en` during prerender and hydration, then switches to the negotiated locale on mount, so there are no hydration mismatches and every route stays static.
- Locale negotiation (`negotiateLocale`): explicit choice (the `NEXT_LOCALE` cookie) → browser languages / `Accept-Language` → `en`. The pseudo-locale is only used when chosen explicitly (cookie, or `?lang=en-XA` outside production).
- Error messages (`lib/errors/messages.ts`) read the same catalog for the active locale and fall back to English.

## Adding a string

1. Add it to `lib/i18n/messages/en.json` under the right namespace (`nav.*`, `wallet.*`, `trade.*`, `errors.*`). Use sentence case; do not claim features that do not exist (see `CONTRIBUTING.md`).
2. Use ICU for variables and counts. Never build sentences with string concatenation:
   `"bought": "Bought {shares} {side, select, Yes {YES} No {NO} other {}} shares."`
3. Pass amounts as already-formatted strings (`lib/format/locale.ts`).
4. Run `npm run i18n:types` to regenerate the typed arguments, then `npm run i18n:pseudo` to regenerate `en-XA.json`.
5. Use it: `const t = useTranslations(); t("wallet.connect")`.
6. `npm run i18n:check` must pass.

## Adding a language

1. Add the tag to `SUPPORTED_LOCALES` in `lib/i18n/index.ts`.
2. Copy `en.json` to `lib/i18n/messages/<tag>.json` and translate the values. Keep every ICU argument name and the `select`/`plural` structure.
3. A key you have not translated yet may be omitted only if it is listed under the top-level `"$fallback"` array; English is shown for it.
4. Run `npm run i18n:check`. It verifies ICU syntax, key parity with `en.json`, argument names, and that the file is up to date.

Translation review rules: never translate contract names, addresses, asset codes (USDC, XLM) or the product name. Do not translate user-generated content (market questions from the backend); never pass it through `t()`.

## Pseudo-locale

`npm run i18n:pseudo` regenerates `en-XA.json`: accented letters and about 30% extra length. Open any migrated flow with `?lang=en-XA` (development only) to look for clipped text or untranslated literals (they show up without accents).

## Tooling

- `npm run i18n:check` (also in CI): ICU validity, key parity with `en.json`, unused keys (a key with no `t("…")` reference), stale generated types. Namespaces resolved by computed key (`errors.*`) are exempt from the unused check.
- ESLint: `i18n/no-literal-text` in `eslint.config.mjs` fails new English literals in migrated files (`Navbar`, `WalletDropdown`). Add a file to that override when you migrate it.

## Not yet done

- `[locale]` route segment, `next-intl` and `proxy.ts` redirects. Moving every route is a large, mechanical change that should land with a passing `next build` for each locale; it was left out so the catalog layer could be verified on its own.
- Components not yet on `t()`: most of `app/markets/quick-view`, `app/copy-trade` (the status, allocation and amount messages are migrated), and `app/premium` checkout.
- `parseUsdc` still throws English sentences (`units.parse.*` is not in the catalog yet).
- The wallet kit's own modal has its own English UI and is outside our control.
